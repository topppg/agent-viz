# Promotional media

- `demo.gif` and `demo.mp4`: the same 10-second scene from the real dashboard,
  1440×1000. Forty-eight invented agents span eight synthetic profile labels:
  Codex ×2, Claude Code ×2, opencode, Pi, DeepSeek, and SDK. They include nested
  subagents, six **needs you** approvals, live activity updates, and a multicolor
  event chart. The capture shows the busy overview, approval details, and a profile
  filter before returning to the full board.
  These labels and tasks are simulated SDK events, **not evidence of native harness
  connections or agents executing work**. The visible synthetic-demo banner stays
  on screen throughout.
- `social-preview.png`: the 1280×640 GitHub social card. `social-preview.html` is its source.
  It reuses the native orbital mark, bundled Space fonts, and existing synthetic
  `docs/dashboard.png`; neither existing README screenshot is replaced.

## Rebuild

From the repository root, with Node.js, `uv`, and an isolated Playwright installation:

```bash
capture_tools="$(mktemp -d)"
npm install --prefix "$capture_tools" playwright@1.62.1
"$capture_tools/node_modules/.bin/playwright" install chromium
NODE_PATH="$capture_tools/node_modules" uv run --with pillow==13.0.0 --with imageio-ffmpeg==0.6.0 python scripts/capture_demo.py
```

If using an existing browser binary, set `CHROMIUM_EXECUTABLE_PATH` to its full path.
If Node is not on PATH, pass `--node /absolute/path/to/node` to the capture script.
The capture tools are not app dependencies and are never added to the lockfile.

The script uses a temporary SQLite store, random local ingestion token, and the real
validated SDK event contract. It never discovers native accounts, reads transcripts
or saved credentials, or configures a summary provider. The dashboard capture blocks browser requests outside
the temporary loopback collector. All session names, activity, and approval text are
invented. Temporary events and frames disappear after capture; no real agent is started.

Before HTTP threads start, a capture-only clock seeds an invented ten-minute event
history through `Store.ingest`. The clock is then restored; fresh events update the
real collector while the browser captures its actual dashboard. No browser API
responses, markup, styles, or app data are replaced.

One hundred sampled dashboard frames play at 10 fps in the MP4. Every other frame
plays at 200 ms in the looping GIF (5 fps). Both total exactly 10 seconds; capture
may take longer. This is an interaction demonstration, not a real-time performance
measurement. The MP4 uses H.264, yuv420p, no audio, and a front-loaded index
(`faststart`) for sharing. The script checks dimensions, frame count, and duration,
plus the GIF's 5 MB size limit. The browser checks 48 visible runs, eight groups,
and a populated event chart before capturing; unit tests check nesting, source
coverage, approvals, historical buckets, and live updates without capture tools.
Capture timestamps and UI animation vary, so regenerated bytes may differ.
This command updates only the GIF and MP4; it leaves screenshots and the social card unchanged.

The social card is a branded composition of the existing example screenshot, not a
new dashboard UI. Upload `social-preview.png` under GitHub repository **Settings →
General → Social preview**. Committing it alone does not activate the preview.
